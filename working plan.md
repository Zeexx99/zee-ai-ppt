# Working Plan — Zee AI for PowerPoint

A blueprint for building the PowerPoint add-in using the same approach as **Zee AI (Excel)** and **Zee AI for Word**.

---

## Part 1 — General steps to create the add-in

### 1. Project setup
- Stack: **React + TypeScript**, built with **Vite**, UI with **Fluent UI v9**, Office APIs via **Office.js**.
- Task-pane add-in (opens as a side pane from a ribbon button).
- Folder structure:
  - `src/services/` — `geminiService` (AI calls), `pptService` (slide read/write), `authService`, `agentService`
  - `src/components/` — chat feed, chat input, settings drawer, quick-action buttons
  - `public/assets/` — icons (16/32/64/80 px)
  - `scripts/make-manifest.mjs` — generates the hosted manifest
  - `tests/` — unit tests
- Use **relative paths everywhere** (`assets/icon-32.png`, not `/assets/...`; build auth URLs with `new URL(..., window.location.href)`) so the same build works on localhost **and** on GitHub Pages.

### 2. Manifest (`manifest.xml`)
- Unique add-in `<Id>` (new GUID — never reuse the Excel/Word ID).
- `<Host Name="Presentation"/>`.
- Ribbon button on the **Home tab** (`OfficeTab id="TabHome"`).
- Use a **unique task pane ID** (e.g. `ZeeAI.PPT.Taskpane`), not the generic `ButtonId1` — duplicates caused problems in Excel.
- Two versions:
  - `manifest.xml` → localhost (development)
  - `manifest.prod.xml` → GitHub Pages URL (generated by `make-manifest.mjs`)
- Validate with `office-addin-manifest validate`.

### 3. AI connection (Gemini)
- Gemini REST client with **streaming** responses.
- Settings drawer with two sign-in options:
  - **Gemini API key** (pasted by the user, stored locally per PC — not shared between computers)
  - **Google OAuth sign-in** (optional; `auth/start.html` + `auth/callback.html`)
- Optional **team proxy** (Cloudflare Worker) so the API key lives on the server:
  - Only forwards `generateContent`, `streamGenerateContent`, `countTokens`
  - Per-person tokens, origin locking, rate limits
- **Cost guard**: warn before sending very large prompts.

### 4. Local development
- Local dev server on its own port (Excel used **3100** to avoid conflicts — pick a different free port for PowerPoint, e.g. **3300**).
- Sideload with `manifest.xml` for testing only.
- ⚠️ Localhost sideloads **disappear when Office restarts** — use them only for development, never as the daily setup.

### 5. Host online (GitHub Pages)
- Create a **public** GitHub repo (`zee-ai-ppt`) under `Zeexx99` (Pages on free plan requires public; the site is public either way).
- Add `.github/workflows/deploy.yml`: on push to `main` → `npm ci` → `npm run build` → generate `manifest.prod.xml` → copy to `dist/manifest.xml` → deploy to Pages.
- One-time: repo **Settings → Pages → Source: GitHub Actions** (forgetting this caused the Word publish failure).
- Add log/temp files to `.gitignore`.

### 6. Helper `.bat` scripts (same set as Excel/Word)
| Script | Runs on | Purpose |
|---|---|---|
| `start-zee.bat` | Main PC | Start local dev server |
| `update-zee.bat` | Main PC | Install deps → run tests → build → push to GitHub (writes `update-log.txt`) |
| `publish-github.bat` | Main PC | First-time repo creation + push |
| `use-online.bat` | Main PC | Point PowerPoint to the hosted manifest (re-run only when ribbon/menu changes) |
| `install-on-another-pc.bat` | Other PCs | Standalone installer (no Node/Git needed), Install/Uninstall/Exit menu |
| `install-zee-hosted.bat` | Any PC | Registers hosted add-in via Windows registry, removes old localhost entries |

### 7. Update workflow
1. Make code changes.
2. Run `update-zee.bat` on the main PC.
3. Wait for the green GitHub Actions check (1–2 min).
4. Close PowerPoint fully and reopen → **Home → Zee AI**.
5. If the build fails, send `update-log.txt`.
- Other PCs pick up updates automatically on restart. If an old version sticks, close PowerPoint and rerun the installer.

### 8. Testing & versioning
- Unit tests for all non-UI logic (vitest; local shim if npm is unreachable).
- Type-check against real Office.js types.
- Show **version + build date** in Settings; bump version on each release.
- Remove source maps from production builds.

## Part 2 — General modifications done (apply from day one)

### Fixes learned the hard way
- **Blank task pane**: Fluent UI portal containers inherited a full-height white background class and covered the UI → scope full-height styles to the app root only.
- **"Preview mode" banner bug** (Word): Office readiness was checked only once → check `Office.onReady` repeatedly until ready.
- **Crash after deploy from cached build**: load the Settings drawer eagerly (not a lazy chunk) + auto-reload once if a stale cached page is detected.
- **Add-in disappearing from ribbon**: caused by localhost sideloading → use hosted manifest + registry installer.
- **Stale add-in registration**: use a new add-in ID if Office keeps loading an old cached version.
- **ResizeObserver warning** shown as a red error → filter it out (harmless).

### Features shared by both add-ins (port to PowerPoint)
- Chat with Gemini (streaming), quick-action buttons, saved-prompts menu.
- **Agent mode** with Gemini function-calling: AI acts on the document with **approval cards**, live step progress, a **Continue** button at the step limit, and **multi-step undo** (failed steps kept, not discarded).
- **Attachments**: images and PDFs via paperclip, paste, or drag-drop.
- Toggleable **web search** and **code execution** (Gemini built-in tools).
- **Chat history** per file; trims oldest messages when storage fills instead of wiping all.
- **Chat export** (copy as text / to new file element).
- **Dark mode** (Settings → Appearance: Auto/Light/Dark + header toggle).
- **Compacting toolbar** for narrow panes.
- Step retries and better reliability for agent actions.

### Word-specific features useful for slides too
- Translate / Rewrite / Summarize, custom quick actions.
- **Protected terms** kept unchanged (ESP, TDH, PIP, GOR, BHP, bbl/d, well names, units).
- **Arabic/English direction handling**: Arabic → right-to-left & right-aligned, English → left-aligned, headings centered; toggle in Settings.
- Configurable **Arabic font** (default "Same as document"; presets Simplified Arabic, Traditional Arabic, Sakkal Majalla).
- **Bilingual mode** (English + Arabic) for text output.

### Petroleum features (Excel) worth bringing to slides
- Turn decline-curve, ESP analysis, and production QC results into slides (charts + summary tables).
- Unit conversion helper.

## Part 3 — PowerPoint-specific plan

### Core agent tools (`pptService`)
- Read: list slides, read slide text/shapes, read selected text, read speaker notes.
- Write: add/delete/reorder slides, insert text boxes & titles, replace text, format text (font, size, color, alignment, RTL), insert images, insert tables, apply layouts/themes.
- Generate: "make a deck from this outline/report", "summarize this slide", "write speaker notes", "fix consistency across slides".

### Notes on the PowerPoint API
- Use `PowerPoint.run(async (context) => …)`; feature support depends on the **PowerPointApi requirement set** — check with `Office.context.requirements.isSetSupported("PowerPointApi", "1.x")` and hide features that aren't available.
- Some actions (e.g. inserting a full slide from Base64 `.pptx`) use `insertSlidesFromBase64` — good for AI-generated layouts.
- Undo: snapshot affected slides/shapes before each agent step.

### Build order
1. Scaffold project + manifest (Presentation host, unique ID, Home tab) → confirm the pane opens.
2. Settings + Gemini API key + streaming chat.
3. Apply the "fixes learned" list above from the start.
4. Set up GitHub repo, Pages, workflow, and all `.bat` scripts → switch to hosted manifest early.
5. Basic quick actions (rewrite/translate/summarize selected text).
6. Agent mode with slide tools + approval cards + undo.
7. Arabic/English direction, protected terms, bilingual mode.
8. Attachments, web search, dark mode, chat history, export.
9. Petroleum report-to-slides features.
10. Tests, version display, `install-on-another-pc.bat` for other PCs.

## Part 4 — Extra lessons & shortcuts from the Excel and Word add-ins

### Reuse instead of rebuilding
- **Copy the Word project as the starting template** (it's the newer, cleaner one), then swap `wordService` → `pptService` and change the manifest host. Most of the app is host-independent:
  - Directly reusable: `geminiService`, `authService`, `agentService` loop, chat UI, settings drawer, dark mode, attachments, saved prompts, chat history/trimming, cost guard, version display, direction/RTL logic, protected terms, bilingual mode.
  - Needs rewriting: anything calling `Word.run` / `Excel.run`.
- Reuse the **same Cloudflare team proxy** — just add the new site origin (`zeexx99.github.io`) to its allowed list and issue tokens; no second proxy needed.
- Reuse the `.bat` scripts and `deploy.yml` — only change repo name, folder, port, and add-in name inside them.
- Longer term: consider a shared `zee-core` folder (Gemini client, chat UI, settings) used by all three add-ins so a fix in one reaches all.

### Keep them separate where it matters
- Different **add-in ID**, **repo**, **port**, **task pane ID**, and **ribbon label** — overlapping any of these caused caching/conflict issues before.
- Use a distinct **storage key prefix** (e.g. `zee-ppt:`) so settings/chat history don't collide with Excel/Word in the same browser storage.
- Settings (incl. API key) are **per PC and per add-in** — the user will need to enter the key once in PowerPoint too (or use the proxy).

### Agent-mode design rules that worked
- Every action that changes the file goes through an **approval card** first; read-only tools can run without approval.
- Give the AI **small, specific tools** (e.g. `setSlideTitle`, `insertTable`) rather than one "do anything" tool — more reliable.
- Send the AI a compact **summary of the presentation** (slide count, titles, selected slide content) instead of the full deck, to keep prompts small and cheap.
- Snapshot before each step for undo; keep failed steps visible with the error so the user can retry.
- Step limit + **Continue** button to avoid runaway loops.

### Testing & deployment habits
- Write tests for all pure logic (formatting, direction detection, prompt building, tool argument validation) — this caught most bugs before running in Office.
- Type-check against the real Office.js types before every publish.
- Check the **green GitHub Actions tick** before testing; fully close PowerPoint (not just the pane) to clear the cache.
- Re-run `use-online.bat` / installer only when the **manifest** changes (new ribbon buttons, icons, permissions); normal code changes load automatically.
- Keep a `backup-before-<change>` folder before large batches of changes.

### Pitfalls to avoid from day one
- Don't rely on localhost sideloading for daily use (add-in disappears on restart).
- Don't use absolute paths (`/assets/...`) — they break on GitHub Pages subpaths.
- Don't lazy-load core UI chunks that the first screen needs (stale-cache crash after deploys).
- Don't let global CSS (height/background) leak into Fluent UI portals (blank pane bug).
- Check Office readiness more than once on startup (preview-mode banner bug).
- Remember GitHub Pages must be enabled (Source: GitHub Actions) before the first publish.

### PowerPoint-specific ideas worth adding
- **Report → deck**: paste or attach a Word report / PDF and generate a slide outline, then build slides after approval.
- **Excel → slides**: attach a table or chart image from Zee AI Excel results (decline curves, ESP analysis, QC report) and turn it into a results slide with key takeaways.
- **Speaker notes generator** and **slide-by-slide summary**.
- **Consistency checker**: fonts, sizes, title capitalization, units, and protected terms across all slides.
- **Text-fit fixer**: shorten bullets that overflow a placeholder.
- **Arabic slide support**: RTL paragraphs, right alignment, Arabic font preset, bilingual title/subtitle slides.
- **Company template mode**: user picks a master/layout once; AI always builds slides with it.
- Detect unsupported API features (requirement sets) and hide those buttons instead of failing — PowerPoint's API coverage is smaller than Excel/Word, and older desktop versions support less.
